## 定位（域界）

本 epic 归属四块，**引擎实现细节与隐私线不归本 epic**：

0. **四层物理分层**（消费接入 → 契约表达 → 路由治理 → 供给执行，单向流动）：分层边界是扩展底线，也是防过度切层的红线——新入口只须转为契约声明、新后端只须实现供给契约，治理机制（静态准入 / 动态准入 / 配额池）只在路由治理层一处；层内禁止为「将来可能」再套壳。
1. **能力需求声明与路由判据**：把「什么时候走端侧」从隐式推断改为显式契约（`CapabilityRequirement` + 判定链 + 端侧适用性对照表）。
2. **端侧算力供给面**：无状态原语 + 任务语义外注 + 三档降级 + 结构化保证；应用级注册中心化。
3. **跨 App 任务形态**：形态 A（消费多来源队列）/ 形态 B（持有跨 App 任务本体）—— 待裁决。
4. **主体与授权粒度**：主体可辨到调用 App 身份；跨 App 写授权基线。

**不归本 epic**：端侧引擎进程模型 / 资产分发 / 准入探针 / 熔断降级（SSOT 在 on-device 各稿）；隐私分级与出站遮蔽（现行立法在 `lib/coordinator/pii_fence.dart`，演进议题见「推后项」）。

## 起点事实（承接设计稿 §2）

- 供给面已有原语形态：`on_device_capability.dart` 的 `complete` + 三档类型化降级 + 独立失败计数 + `[DEGRADE]` 留痕。
- 路由判据是两个间接信号：请求是否携带工具（`hybrid_cloud_engine.dart`）、工具面是否全本地（`hybrid_assembly.dart`）。二者把「要动别人数据 / 要调工具 / 复杂度 / 端侧适用性」压成一个布尔判断。
- 端侧适用性数据已有来源未成表：真机基准已归档（`assets/model-specs.json` + on-device decisions.md 三档基准），驱动器 `on_device_bench.dart` 现成；任务类型 × 可行性对照表缺位。
- 跨 App 通道与信任已成型：Binder 通道统一 MCP 语义；本地插件发现 + 签名白名单分级；`host` 虚拟服务 Allowlist 导出。
- 单次任务语义已完整但来源私有：接缝侧消费链具认领/心跳/推理/回写 + 幂等 + 毒丸 + 熔断 + catch-up + 对账；服务标识绑单包名常量。
- 主体粒度通道级：`Actor` 仅 owner / external(id)；Binder 主体推导未接入。
- 能力上限有声明式落点：`RunProfile` 三档 + `capabilitiesFor` 唯一映射点 + `RunCapabilities` 四维。

## 裁决记录（gate 已解除）

| # | 裁决 | 依据 | 收敛条件 |
|---|---|---|---|
| **D1** | **形态 A**（Worker：消费多来源任务队列） | 与来源 App 零冲突，来源保持任务事实源；落地量约为形态 B 的四分之一；当前无多 App 双向穿梭的强业务诉求 | 形态 B 解封条件（任一即重开立项）：① 两个以上来源 App 需共享同一任务上下文；② 形态 A 落地后出现「任务状态须被第三方 App 读取并据此决策」的真实案例；③ 单任务跨 App 步骤数稳定超过五步且需中途可观测 |
| **D2** | **a**（供给面只供无状态完成能力，任务语义外部注入） | 供给面保持通用原语，端侧不成为任务语义中心；语义外注不新增机制；内置模板会使端侧资产与宿主业务代码耦合发版，与资产独立分发现状冲突 | 出现「调用方必须接受固定语义才肯调用」的实证协议要求时重开修订 |
| **D3** | **分级策略**：网络可达且冷态 → 分流云端（理由码 `COLD_LOAD_BYPASSED_TO_CLOUD`）；网络不可达且冷态 → 装载等待并渲染加载态（理由码 `OFFLINE_COLD_LOAD_WAIT`） | 分流云端对在线交互最平滑；网络不可达时云端不可用分流必失败，等待装载是唯一可完成路径 | 装载等待期间的取消语义（放弃本轮等待而非中止装载）在 W2 时效判定落地时定死 |
| **D4** | **① 迁到语义注入路径**（不设过渡豁免） | 豁免会让过渡代码长期留存并增分支维护成本；迁移后宿主成为供给面第一个种子客户，在 W3 内闭环验证语义注入通道，开放阶段无须推翻重写 | **前提**：端侧供给面契约须承载约束解码（规格随生成参数下发、Runner 侧自治匹配），否则 Skill 化的分类无输出格式保证 = 迁移即能力降级；前提不满足则本裁决挂起，W3 先补契约 |

裁决来源：外部评审第二轮（形态取舍、冷热态分级、语义注入破局、调用方身份取证、内存门槛）+ 代码实证复核（约束解码在端侧契约上不存在、调用方身份在现有实现上不存在、内存地板现有线为 1GB）。

## 设计约束（评审轮确立，具约束力）

| # | 约束 | 出处 |
|---|---|---|
| K9 | **准入落空分两类**：资源故障（窗口不足 / 时效不可接受 / 端侧未就绪 / 后端被排除 / 内存低于地板）分流云端保产出；**治理违规（配额超限）快速失败**，类型化异常，不切云 | 评审第三轮·配额击穿商业与安全边界（配额超限切云等于把调用方的算力成本转嫁宿主云端账单与并发容量，配额形同虚设） |
| K10 | **声明排除位** `localOnly` 显式禁止云端，落空时快速失败；与 `canRunOffline`（下限约束）正交——下限管「云端不可达时仍要能完成」，排除管「任何情况下都不许出境」 | 评审第三轮·离线与隐私偏好被静默切云 |
| K11 | **打断是协作式不是抢占式**：底层算子阻塞不可切分，中断只在生成循环检查点生效；等待窗口耗尽不得假设打断已生效，按策略性降级处置（切云或显式上浮等待），**不得以重启引擎腾算力**（重启即冷装载 = 秒级装载 + 前台卡顿） | 评审第三轮 + on-device P2-13（响应性未实证、抢占等待 1.5s 可能被 stopStream 吃掉） |
| K12 | **供给面契约暴露可选前缀复用句柄**，引用既有前缀缓存与上下文回滚能力，不新建缓存机制；收益未实证前不承诺命中率 | 评审第三轮 + on-device P2-12（`GenieSession.query` 每请求 `w.reset()` 与前缀复用声称矛盾，SDK 无源码未实证） |
| K13 | **导出面门禁四类**（可见性 / 权限 / 标注 / **资源治理**），算力导出项须过资源治理门禁；不新造命名空间（导出面分派判定是通用规则，不携带条目治理语义） | 评审第三轮（部分采纳：驳回「dispatcher 臃肿」与「新造 compute__ 命名空间」，采纳「行为权限与资源额度解耦」） |

| K14 | **基础原语为流式**，全量完成是聚合包装；取消随订阅退订下沉。流式化是**暴露既有能力**（端侧引擎契约本就是流式，原语入口把流聚合掉了） | 评审第四轮·流式与交互级时效自相矛盾 |
| K15 | **结构化输出场景禁用截断降级档**（被截断的结构化产物必然解析失败）；约束解码失败须携带**跨端可归一**的输出规格回退云端，各引擎原生方言由各自 Runner 归一到中间形态 | 评审第四轮·约束解码失败降级未定义 |
| K16 | **人工审批不得在算力占用期内同步等待**：判定需确认即释放执行槽并返回结构化挂起态，授权后由调用方发起新一轮；对宿主自身确认卡同样成立 | 评审第四轮·审批弹窗霸占单重入槽 |
| K17 | **调用方进程死亡须联动打断算力**：平台侧为调用方链路注册死亡代理，检测到对端死亡即协作式打断并作废本次调用；既有方向的死亡代理不覆盖反向路径 | 评审第四轮·孤儿执行算力泄漏 |
| K18 | **配额记账事务语义**：并发数进入槽占用、退出必释放（无论成败或切云）；频次仅在实际占用算力并产出时计入；宿主资源问题导致的被动切云不扣调用方配额，但云端成本仍归宿主 | 评审第四轮·配额回滚与不扣减缺失 |
| K19 | **就绪判定含驻留资产匹配度**；前台交互活跃期不得因后台任务触发换驻留——多资产并存时同一时刻只驻留一份，换驻留即换装载，单装载纪律下换装载等同进程重建（秒级装载 + 前台卡顿） | 评审第四轮·多资产换入换出震荡 |
| K20 | **单轮产出边界**：供给面原语单次无状态、不驱动工具往返；往返由宿主工具环推进（聊天路径复用既有工具环；任务消费路径单次单轮，多轮由任务来源方推进） | 评审第四轮·工具回注后无人驱动下一轮 |

| K21 | **配额超限在路由治理层抛类型化治理异常快速失败，不切云**（与落空两分类同口径：资源故障类落空才分流云端；治理违规类落空快速失败） | 评审第五轮·正文残留旧表述导致自相矛盾 |
| K22 | **挂起态载荷含待确认操作的意图与参数 + 继续签名**（超长载荷可用既有引用句柄承载）；**宿主不驻留等待实例**，调用方凭签名与用户确认凭据在新一轮重入 | 评审第五轮·挂起态缺唤醒反投契约 |
| K23 | **槽冲突的消费纪律 = 放弃认领 + 退避重试，禁误标终态失败**（终态失败不可重试，一次前台交互即足以永久判死排队中的后台任务）；接缝须补「放弃认领」原语——现行仅认领 / 心跳 / 回写三段 | 评审第五轮·心跳续期与单槽排他死锁 |
| K24 | **跨 App 导出首期只暴露聚合完成面**；跨 App 流式留待后续，届时须显式声明承载机制（进度通知扩展或双向通道）并处理流中断与半截产物清理 | 评审第五轮·跨 App 流式通道真空 |
| K25 | **时效判定按时效档分表**：交互级冷态优先分流云端（秒级代价落在可感知路径）；批处理级冷态且偏好本地时触发异步显式装载并排队，**不分流云端**（否则偏好本地声明在批处理场景形同虚设） | 评审第五轮·偏好本地被真值表消解 |
