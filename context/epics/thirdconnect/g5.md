# G5 收尾：Wi-Fi IP 展示 UI + §9.6 背压并发信号量

> 契约 SSOT：docs/design/thirdconnect.md §7（物理通道：局域网 Wi-Fi 展示 IP + Token）/ §9.6（PC 突发并发背压击穿：单 server max_concurrent=4 硬上限排队）。
> 定位：G5 物理通道主体（`0.0.0.0:8766` + Bearer Token、ADB forward、Tailscale）已随 G1/G4 就绪；本卡收尾两件。

## 1. 交付物

1. `lib/gateway/gateway_backpressure.dart`——`PerServerBackpressure`（§9.6）：
   - per-server 计数信号量（惰性建），`max_concurrent = 4` 硬上限（`kMaxConcurrentPerServer`）；
   - 超上限 FIFO 排队等待，槽位随完成**零间隙移交**队首等待者（计数不回落，交接不抖动）；
   - handler 接线：只包**真实执行段**（`face.client.callWithProgress`），L2 确认等待不占并发槽（45s 人工确认不吞吞吐量）。
2. Wi-Fi IP 展示（G5 UI）：
   - `GatewayController.lanAddresses()`：`NetworkInterface.list` 枚举非回环非链路本地 IPv4（零原生代码，免定位权限拿 SSID 的坑）；失败 DEGRADE 返空；
   - chat_page 设置面板：网关运行中副标题实时展示 PC 可配 URL（`http://<IP>:8766/mcp` 多地址「或」连接；ADB 场景提示 127.0.0.1）；面板打开与开启成功两个时机刷新。

## 2. 验收（全部通过）

  2. per-server 隔离：A 满载（1 槽）不阻塞 B（即时执行）；
  3. handler 级穿透验证：6 并发 tools/call 同一 server → 假传输在途峰值 ≤ 4，排队者全部执行。

## 3. 关键发现（测试基建踩坑，记入教训面）

- 假传输的并发计数递减**必须放 async* 生成器的 finally**：`McpClient.callWithProgress` 消费完终帧即在 `await for` 内提前 `return`——生成器被取消，yield 之后的普通尾码不执行，仅 finally 保证运行。计数泄漏曾致峰值误报 6（4 并发 + 2 泄漏），信号量本身行为正确。
