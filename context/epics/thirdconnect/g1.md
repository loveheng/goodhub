# G1+G2：嵌入式网关服务器 + 聚合单入口

> 契约 SSOT：docs/design/thirdconnect.md §7（Host+Gateway 双角色）/ §9.2（tools/list_changed 下行）/ §9.6（背压，未做）/ §10.4（TC12，收窄版）。
> 定位：PC（Cursor/Claude）经 `http://<手机IP>:8766/mcp` 单入口操作手机内全部生态（本地 Binder 插件 + 远端 HTTP server），对命名空间完全透明。

## 1. 交付物

1. `lib/gateway/mcp_gateway_handler.dart`——网关协议处理器：
   - `tools/list` 全量聚合（G2）：全部已挂载 face 的缓存 Schema 前缀化 `<server_id>__<tool>`（ToolRouter 同款前缀语义）；
   - `tools/call` 按前缀分发（G2）：剥前缀直达 `face.client.callWithProgress`（per-call 进度闭包，并发安全），progress 帧经回调上行给服务器层转 SSE；
   - 工具目录变更广播（§9.2）：`notifyToolsListChanged()` → broadcast 流。
2. `lib/gateway/gateway_server.dart`——嵌入式 Streamable HTTP 服务器（G1）：
   - POST `/mcp`：按 `Accept` 回单 JSON 或 SSE 帧流；`initialize` 下发 `Mcp-Session-Id`，后续请求强制回带（缺失/未知 → 400）；
   - GET `/mcp`：SSE 订阅通道，`tools/list_changed` 主动下行（§9.2，PC 自动静默重拉 tools/list）+ 15s 心跳注释帧（TC12 收窄版，仅 GET 流）；
   - Bearer Token 校验（G3 最小件）：`requiredToken` 非空即强制 `Authorization: Bearer <token>`，无/错 → 401。
3. `lib/gateway/gateway_controller.dart`——装配与生命周期：
   - 双源装配：本地插件零配置发现（`localPluginDiscovery.scan`，系统托管）+ 手填 HTTP 端点（`ServerEndpointStore`，用户托管）→ negotiate → listTools → face；
   - sampling 反向请求接线（best-effort，失败仅 -32601 拒绝不起服失败）；
   - 包变更订阅 → 全量重扫重建 face → 目录变更下行（§9.2 联动）；
   - `GatewayController.shared` 进程级单例。
4. UI 接线：`chat_page._openSettings` 顶部「PC 远程网关（:8766）」开关 + 配对 Token 输入（SharedPreferences `gateway.token` 持久化）。

## 2. 关键实现决策

- **独立装配，不挂聊天会话**：网关自建 face 集（与 chat_page 装配口径等价但生命周期独立）——PC 远程调用不依赖手机端是否开着会话；
- **tools/call 直达 `face.client`** 而非走 `ToolRouter.execute`：绕开激活集门槛（PC 端无 JIT 激活概念），且拿到 per-call `onProgress` 闭包（face 级单回调在并发下会串流）；
- **dart:io `IOSink.flush()` 竞态红线**：`flush()` 以 `_isBound` 互斥、与 `close()` 相撞同步抛 `StateError`——全文件不显式 flush（socket 写出本就自行调度，flush 只保证投递 future）；
- **TC12 收窄**：GET 订阅流 15s 心跳；tools/call 流式期间由 progress 帧天然喂狗，无 progress 长调用的 Keep-Alive 注入留后续收口。
