# GoodHub UI 设计规范 · 运行时控制台风格

> 本文是 GoodHub 视觉与交互语言的 **SSOT**（Single Source of Truth）。风格定位：**工业实用主义（Industrial Functionalism）× 现代控制台质感（Modern Console / Cockpit Aesthetics）**——Linear / Raycast / Vercel 的移动端延展，融合 Material 3 无边框层级逻辑。
>
> 设计隐喻：GoodHub 不是「聊天室」，而是**随身进程管线与调度控制台**。基调关键词：克制、精准、高密度、确定性状态。传达「掌控系统与应用生态」的安全感，而非「逗弄聊天机器人」的玩具感。
>
> **三拒绝**：拒绝过度拟物；拒绝大面积渐变发光（Cyberpunk 玩具感）；拒绝玩具式大圆角。
>
> 需求映射见 [requirements.md](requirements.md) F5；模块归属见 architecture.md §5。代码落点规范（tokens/组件目录）由项目 skill `.agents/skills/goodhub-ui/SKILL.md` 声明，不在本文重复。

## 1. 色彩体系：功能状态驱动（Semantic Color System）

背景采用低饱和冷中性色，**高对比度色彩全部留给系统状态**，不做装饰性用色：

| 色彩角色 | 色板（Material/Tailwind 参考值） | 语义与映射组件 |
| --- | --- | --- |
| 底色与基底 | 深色 Zinc 900/950；浅色 Slate 50/100 | 页面背景、阅读轨底色，长注视不刺眼 |
| L1 静默/就绪 | Emerald 400 / Cyan 500 | 只读工具执行、心跳探活正常、轻量药丸提示 |
| L2 写操作警示 | Amber 500 / Orange 400 | 写操作二次确认、跨 App `$ref` 联合授权卡片 |
| 危险/熔断/Abort | Rose 500 / Crimson | 胶囊一键中止、连续报错熔断排查卡片、准入被拒节点 |
| 数据指针与资源 | Indigo 400 / Violet 500 | `$ref` 暂存池句柄、`resources://` 数据引用标签 |

## 2. 双轨字体排印（Dual-Track Typography）

- **阅读轨（Content）**：高易读无衬线（Inter / Roboto），标题级数严格，行高 1.5~1.6；代码块背景微深、横向平滑滚动。承载流式 Markdown。
- **操作轨与元数据（System / Telemetry）**：凡 `Trace-ID`、端口 `:8766`、参数 JSON、Schema 名、Token 计数、引擎名（`local:qwen-4b`），**强制等宽字体**（JetBrains Mono / Roboto Mono），字号 11~12sp，微弱底色容器包裹。

## 3. 关键界面模块设计语言

### 3.1 顶部状态胶囊（Top Status Capsule）

- **形态**：极简状态指示（7px 状态点 + 等宽相位文字，1px 半透明描边容器可选）。**2026-10-14 起 M1 形态收敛为「底部输入条内嵌」**——状态点+相位居输入条左位、`[ABORT]` 居右位，不占独立行、空闲期不再显空行（原「应用内顶部内嵌胶囊」形态废弃，StatusCapsule 组件保留供联调页等非输入场景复用）。
- **落地阶段**（对齐 architecture.md §5）：**M1 为应用内顶部内嵌胶囊**（应用内组件，非系统悬浮窗）→ M3+ 演进为系统通知/悬浮形态。禁止 M1 直接上系统 Overlay 窗权限。
- **布局**：
  - 左：状态微动效——端侧离线加载/引擎唤醒时**呼吸点**（对齐 N6「离线引擎唤醒中」）；长任务 `Running(progress)` 显示微型百分比（对齐 F1.15 `$/progress`）。
  - 中：当前调度阶段，等宽字体（如 `goodshare::list_items`）。
  - 右：高反差低误触的红色 `[ABORT]` 圆点/文本，点击触发重度震动（对齐 F1.13 / `abort_task` 特权工具）。
- **引擎态指示（第四态）**：端侧/云端引擎切换（F2.4 降级判据触发）时呼吸点变色 + 等宽标注当前引擎名。

### 3.2 双轨消息流（Dual-Track Stream）

- **视觉隔离**：彻底抛弃左右对投气泡。阅读轨与操作轨**同一纵轴排版**，以卡片形态与边框语义建立类型隔离。
- **操作卡片状态机**（覆盖三种卡片：参数确认 / 执行状态 / 熔断排查）：
  - **结构**：8~12px 微圆角，内凹或微浮起扁平卡片，**左侧状态竖条**指示语义色（Amber=待确认、Emerald=执行中/成功、Rose=熔断/中止、灰阶=终态）。
  - **参数区**：入参用折叠式键值对展示，严禁大段无排版 JSON。
  - **熔断排查卡片**（对齐 architecture.md §5）：Rose 竖条 + 结构化错误摘要（等宽字体）+ 三操作（单步重试 / 跳过 / 人工接管）。
  - **终态锁定**：用户确认/拒绝/取消后，卡片锁定为灰阶弱化态，操作按钮消失，替换为「✓ 已于 10:42 确认」「✕ 已拒绝（原因：…）」「⊘ Cancelled」——日志不可逆的审计感（对齐 F1.13 Cancelled 终态与 N4 全链路审计）。

### 3.3 服务与配置大厅（Hall & Integration Hub）

- **形态**：路由器管理后台/云平台控制台式卡片阵列。
- **节点模块**：每个下挂 Server 展示为「节点」，含端口号、延迟毫秒、在线绿点、已暴露工具计数（等宽字体）。
- **鉴权态必须展示**（对齐 F1.17 同机零信任）：区分**已授权 / 待授权(403)**——准入被拒用 Rose 色，禁止与「用户主动卸载」的灰阶混淆。
- **挂载/卸载开关**：微型物理开关质感，强化 Dual-Role 节点的本地总线心智。

## 4. 移动端（Flutter）质感细节

1. **触觉反馈系统级嵌入**：L2 拦截卡弹出→双击警示震动；Abort/熔断→重度确认震动；L1 静默执行与药丸完成→极轻微 tick。
2. **动效克制**：避免弹性阻尼（Spring），用紧凑减速曲线（Decelerate / Ease-Out），转场 150~200ms。
3. **边缘处理**：卡片分割用 1px 细边框（0.5~1dp，10%~15% 不透明度白/深灰），**不用大范围弥散投影**，保证高信息密度下边界分明。
4. **Token 化落地**：色彩/字体/圆角/边框/动效时长全部收敛为 design tokens（Flutter `ThemeExtension`），组件内禁止散落魔法值——落点见项目 skill `goodhub-ui`。
