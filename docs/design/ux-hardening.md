# 普通用户可用性加固（UX Hardening）

> 来源：2026-10-16 普通用户视角全库体验盘点（聊天主功能面 + 设置/记忆看板/更新/信任弹窗 + `lib/` DEGRADE 标记扫描 20 处，关键指控已逐条 file:line 核对）。
> 与 page-revamp 的关系：page-revamp 管视觉规范与信息结构（P0~P2 已全部清零）；本 epic 管**「出错后的用户之路」与冷启动**——可用性、错误反馈、术语白话、危险操作权重、DEGRADE 用户可见性。两域不重叠，规范 SSOT 仍是 [ui-design.md](../product/ui-design.md)，本文只记可用性整改范围与分解。

## 1. 范围（Scope）

- 聊天主功能面：冷启动断链、错误自救、运行中出口、会话管理、决策卡可理解性（`chat_page` / `conversation_drawer` / 双轨卡片族）
- 辅助功能面：设置页 / 记忆看板 / 更新页 / 信任弹窗的错误反馈、文案、危险操作权重
- 内部术语的用户面白话层（BYOK、Skill 覆写/CoW、跨源授权/句柄/禁盲签、会话装配、锚点、熔断、围栏、private tier）
- DEGRADE 标记的用户可见性治理（仅治理「用户效果变差但不报错」的面；`hybrid_cloud_engine` 两处偏危险方向另行评估收紧）

## 2. 问题清单与优先级（P0 → P2）

### P0 · 冷启动与错误自救（断链最严重段）

| # | 问题 | 落点 | 方向 |
|---|---|---|---|
| 1 | 未配置服务时发送**整页 push 设置页**（用户像被劫持，不知怎么回来）；空态是纯文本无可点入口 | `chat_page.dart:591-602`、`:1032-1033` | 轨道内引导卡 + 「去配置」按钮；返回后输入内容保留可续发 |
| 2 | 错误路径无自救：异常统一 `✕ 任务中断：$e` 原始异常直怼轨道，无重试无指引；连接中断仅一行文本 | `chat_page.dart:890-892`、`:744-752` | 错误文案白话翻译 + 重试入口 + 下一步指引 |
| 3 | 辅助面初始化失败反馈缺失：settings 一处失败打死整页（其余面板可用被替换）；update `_bootstrap` 无 try/catch 失败后按钮永久灰死无报错 | `settings_page.dart:525-528`、`update_page.dart:46-68` | 面板级错误隔离 + 分色错误态 + 重试 |

## 3. 非目标（Non-goals）

- 不改视觉规范/主题/Token 纪律（page-revamp 域，SSOT = `ui-design.md`）
- 不重构内核 DEGRADE 的兜底方向（除 `hybrid_cloud_engine` 两处评估收紧）；不新增第三方依赖
- 不做新功能扩张（排队发送等新交互形态须先拍板再进范围）

## 4. 验收口径

- 新用户冷启动路径可走通：未配置 → 轨道内引导卡 → 去配置 → 返回续发，全程无整页劫持
- 每条错误路径有：白话文案 + 至少一个自救动作（重试 / 去设置 / 取消），错误与普通提示视觉分权
- 危险操作（信任并挂载 / 记忆粉碎 / 安装更新 / 撤销信任）主次按钮权重符合安全 UI 惯例，均有确认与后果说明
- DEGRADE 治理项逐条落地：用户可见提示 或 收紧结论（记入 devlog）
- `flutter analyze` 0 新增 issue；相关 widget 测试全绿
