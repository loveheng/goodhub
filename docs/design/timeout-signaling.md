# 超时信令下沉优化方案（临时 epic）

> 根因总纲：这批"限定时间判定失败"的超时，本质是**计时器在替一个本该由对端主动上报的状态兜底**。根治方向 = 把状态信令下沉到 native/协议层；下沉完成前，现有超时是合法兜底，不是 bug。
> 评估结论（2026-11-05 会话对代码逐条核实）：时限落点断言全部属实；三处修正已吸收进本方案——① 看门狗**不可撤除只能降级**（进程冻结时信令也发不出来，进程级兜底永远需要外部计时器）；② 熔断 L2 已有部分证据分级（驱动不兼容/ION 失败已排除），勿按"完全没分级"重做；③ MCP 终帧根治是跨仓契约变更（goodhub-mcp-sdk 单副本）。

## W1 低风险 Dart 侧（高优先级，先行）

1. **熔断 L2 解锁接 driverFingerprint**：L2 24h 锁解锁条件增加驱动指纹变更（资产/驱动更新即解锁）。锁与计数口径维持 P2-9 已拍板口径（自然日累计、24h 锁，2026-11-01），本项只增强解锁侧，不动判据。
   - 落点：`lib/llm/on_device_circuit_breaker.dart`（现排除清单已存在，只增强解锁侧）。
   - **施工口径（2026-11-05 评估）**：指纹提取走既有 `deviceFingerprint` 通道（`Build.FINGERPRINT` 系统属性直读，`EngineServiceBridge.kt`），零副作用、不依赖引擎初始化，熔断锁定期间可安全读取——不存在「锁着取不到指纹」死锁面。实现 = L2 触发时随锁截止时间同写触发时指纹，`isBroken` 判定前比对（指纹不同 → 解锁）。
   - **遗留项**：`Build.FINGERPRINT` 仅随系统 OTA 变化，不含 QNN/Skel 运行库版本（待 SDK 头文件接入后并入指纹串）——自更新通道换 AAR 不触发解锁，接入前为已知盲区。
2. **准入探针异步化**：AdmissionProbe 从导入路径同步阻塞（10s 硬超时、不可取消）改为后台异步跑、结果写画像；与已拍板的 DispatchProfile 探针轮合并施工。
   - 落点：`lib/llm/on_device_admission_probe.dart`。
   - **首问空窗兜底（2026-11-05 评估，既有契约非新决策）**：画像缺失/探针未跑完 = 未知后端，路由交既有降级链自试（探针编排层既有语义：失败不锁死端侧）——首问体验与探针机制上线前一致，无需占位 UI。
   - **施工约束**：探针 = load → 真生成 32 token → unload，占用唯一 EngineSlot；用户请求活跃/生成在途时探针让位（推迟或放弃本轮，探针本身可重入 `probeIfNeeded`），禁与首问在单槽上相撞。

## W2 装载链异步化（中优先级，动 :engine 接缝）

3. **装载进度事件 + 可取消装载**：native 侧推 loading 进度帧，Dart 侧 90s 硬等改为进度可见、可取消；B-2 语义（超时=请求侧退出、装载后台继续）保持。
   - 落点：`:engine` AIDL 接缝 + `lib/llm/on_device_engine_aidl.dart:134-187`。
   - **接缝纪律**：动接缝须同轮修 goodshare 仓 `docs/design/ai-app-split.md`。
   - **取消语义（2026-11-05 评估）**：cancel = 请求侧脱钩（仅脱离 `_awaitLoadTask` 有界等待），**禁接 `_loadGen` 代次作废**——否则误杀后台装载、复现「老装载后台跑满 I/O、状态错乱」。装载并发互斥已由既有两层覆盖（Dart `_loadTask` 单飞 + modelId 去重合并；`:engine` 单进程单装载纪律），无需新增 native 锁。

## W3 native liveness/进展帧信令（中优先级，需立项）

4. **引擎存活/进展信令下沉**：native 层上报 liveness 与进展帧，数据流活体证据替代字节间隙猜测。
   - 受益超时族：无进展看门狗 30s（误判部分）、受理 10s、票据 3s、waitReady 10s。
   - **红线（评估修正）**：看门狗**降级为进程级冻结/死亡兜底，不撤除**——进程冻结场景信令自身不可达，外部计时器不可替代。
   - **信令形态（2026-11-05 评估）**：token 数据帧（~40ms 微批）本身即最硬 liveness 证据，禁按 token 频率发独立心跳；独立 `LivenessTick` 仅覆盖数据流空档（prefill/首 token 前、长间隙 decode），周期下限 **2s**（看门狗 30s 下失联判定前有 ≥15 个 tick，500ms 属过度保守、白耗 Binder）。
   - **施工约束（既有拍板，勿拆）**：TTL 定时器代次作废双件（startGenerate removeCallbacksAndMessages + EngineLifecycle isBusy）不拆；在途流五条收敛路径的 session.ready 守卫不拆。

## W4 MCP 终帧框架补发（低优先级，跨仓）

5. **终帧必达**：通道关闭时由框架补发/标记终帧，正常路径接管消费者判定。
   - **兜底保留（2026-11-05 评估）**：消费者 120s idle **不删除**——进程崩溃（SIGSEGV）/Socket 异常断连场景补发终帧不可达，idle 是进程级最后防线；正常流程下不再被触发即可。
   - **前置**：先改独立仓 `loveheng/goodhub-mcp-sdk` 的 `:contract` 模块（契约物理单副本），`toolbox run check-contract-sync` 校验版本绑定；本仓随后跟进。
